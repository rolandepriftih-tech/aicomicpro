# DSH 工作检查清单（AI Comic Pro）

来源：2026-08-26 用户反馈"你总不明白我的意思""给了图也做不出一模一样的""反复修不对"后，DSH 承诺的固定工作方式。

## 动手前（每次收到需求/图/bug 报告）

- [ ] **有图**：把图里每个元素的位置/大小/颜色/间距用文字列全，发给用户确认"对，就是这样"后才动手
- [ ] **有歧义词**（"一行""一列""悬浮""窗口""这个"）：先复述理解，用户点头才动手
- [ ] **尺寸术语统一**：一律用"横向/纵向 + 数值"（如"横向 900px""纵向 260px"），不用"宽/高/长"（中文歧义：宽度可能是长度、高度可能是宽度）；用户说"宽度/高度/长度"时，复述成"横向?px / 纵向?px"确认
- [ ] **位置术语统一**："上方/下方/左侧/右侧"要区分两种含义：(a) 覆盖在 X 内部的上/下部（悬浮层，如"悬浮条覆盖在图片顶部"）；(b) X 外部、紧贴 X 的上/下/左/右侧（独立条/面板）。用户说"X 上方/下面"时，复述成"覆盖在 X 内部？还是 X 外面一条？"确认；涉及单侧内边距/偏移（如"顶部 20px"）用"上/下/左/右 + 数值"说清是哪一侧
- [ ] **间距维度**："XX 与 XX 之间"要确认"紧贴无缝（间距 0）"还是"留间距（多少 px）"；用户说"窗口与窗口之间"默认指紧贴、没有空间，不要默认加 gap/margin
- [ ] **参考截图 = 标准**：元素放哪、长什么样，照做；不按自己审美发挥
- [ ] **明确"一样"的标准**：像素级还是布局一致，动手前问清

## 修 bug 时（收到"坏了/没变/消失"报告）

- [ ] **先追完整数据流**：page → 中间层 → 底层组件 → 存储，每一层查 props 有没有传、数据有没有存，一次查透，不打地鼠
- [ ] **找到根因**再改，不修表面症状
- [ ] 同类问题查所有入口（按钮/键盘/API/刷新/多卡片类型）

## 报告前（改完代码后）

- [ ] **自己验证**：走一遍完整流程（上传→显示→刷新→还在；点按钮→有反应），验证过了才说"修好了"
- [ ] 明确报告"我验证了什么"，不让用户当测试员
- [ ] tsc / 测试 / build 全过才算完成

## 历史教训速查（本仓库反复踩过的坑）

- props 漏传已发生三次：PreviewPanel 中间层、page.tsx 直接层、VideoNode 润色配置层——涉及数据流必逐层查
- 显示逻辑要覆盖所有数据源：imageUrl / referenceImage / assetImageUrls[按资产名] / panelImageUrls
- "排成一列"≠"每项一行"；"一行排列"= 不换行（禁 flex-wrap）
- 卡片下方弹出 = 独立浮层（absolute），不是内嵌展开（套娃）
- 参考截图里的悬浮条 = 覆盖在图片上的 absolute 层，不是嵌在内容流里的一行
- React Flow 的 Node 类型会遮蔽 DOM Node，判断要用 instanceof
- .env.local 无 GEMINI/OPENAI key，API key 全靠 UI 传入——检查配置是否真传到请求处
